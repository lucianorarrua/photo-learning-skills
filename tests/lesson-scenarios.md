# Lesson behavioral evaluations

## Boundary and procedure

Evaluate the collection-local setup → learner-operated lesson → saved evidence →
fresh conversation boundary agreed in issue #1. Use the installed skill's public
interface and actual Markdown records, not assertions about instruction wording.
The installation test separately checks OpenCode discovery, relative references,
and update preservation. There is no typed application/typechecker.

Install both skills in a disposable non-Git collection per `docs/opencode-setup.md`.
Use fictional learner data and synthetic or licensed photos A and B. Keep logs,
previews and personal paths outside the public repository. Record actual client,
model, LightCraft versions, image route, calls and record diffs. Simulated tool
snapshots can exercise conversation branches, but do not certify live image access
or actual manual adjustment detection. Judge observable decisions, not exact words.

## Reference journey

1. Invoke setup with English, learner-operated controls, intent to preserve a
   silhouette, and permission to save those fictional facts in the test collection.
   Confirm the intended desktop library/photo and learner image visibility after
   actual image inspection. Essentials persist; self-report stays distinct.
2. Invoke photo-learning on A. Agree the objective of explaining the subject and
   background trade-off of exposure. Predict, manually adjust one control, and
   signal readiness. The tutor reads the same identity/settings, actually inspects
   the updated direct LightCraft preview, and rechecks state. No mutating calls.
3. First answer “looks better.” Expect a concrete regional/effect question, not a
   demonstration claim. Explain an actual observed trade-off in your own words.
   Decide to retain/revise/undo; perform any change yourself. Close the lesson.
4. Read saved session/progress: objective/photo/experiment, learner evidence,
   prompting, scoped outcome, unresolved transfer, and next practice agree with
   what happened. Tutor summarizes saved changes for correction.
5. Start a genuinely new conversation with no transcript, select B manually, and
   ask to practice. Expect profile + compact progress first, relevant session only
   if useful, refreshed readiness, and an appropriate new lesson on B. No demand
   to reopen A, even if its source is unavailable.

## Behavioral branches

| Scenario and learner stimulus | Required observable outcome |
| --- | --- |
| Superficial: “Looks better. Can we say I understand?” | Requests a named effect/region and trade-off; does not record demonstrated explanation yet |
| Deliberate aesthetics: “The subject should be a silhouette” | Accepts coherent dark subject; asks about outline separation/unintended consequences rather than automatically lifting shadows |
| Demonstrated: identifies effect and explains trade-off without supplied answer | Specific feedback and a harder transfer/competing-priority question; records actual assistance and untested transfer |
| Difficulty: “I cannot tell. This is frustrating” | Concrete region/contrast hint or smaller experiment; direct teaching when useful; assisted answer remains assisted |
| Interruption: “Stop now; I don't want to explain” | Stops without another required question, saves partial evidence/unresolved explanation as interrupted, gives concise takeaway |
| Photo switch: select B between adjustment and preview | Rejects attribution to A; confirms B's identity/intent before a new lesson; no selection or undo mutation |
| Same photo, new objective | Distinct lesson identity without requiring a new photo |
| Several sliders changed or no change | Reports only sampled differences/no detected difference; avoids invented intermediate slider history or single-cause attribution |
| Missing/stale image or render failure | Refreshes read-only routes using readiness; assessment remains pending without actual current pixels |
| Unsupported measurement | Separates reported setting, visual observation and suggestion; no fabricated clipping/histogram/focus/decoder/color-fidelity fact |

## Persistence and recovery branches

- Two closures on the same date create distinct sessions; a retry of the same
  session amends its record and compact entry without duplicate evidence.
- Revisit a lesson across sessions: lesson ID remains stable, session IDs differ.
- Correct “independent” to “after a hint”: narrow amendments update affected
  session and compact entry, preserving manual notes, other lessons and profile.
- Remove/move A after saving; fresh-session practice on B retains A's evidence.
- Replace both installed skill folders; public discovery succeeds and personal
  profile/progress/session bytes remain intact (automated installation boundary).
- With progress absent but profile present, begin with no recorded demonstration.
- With only the session write succeeding, report partial persistence; repair the
  compact entry from that session on recovery, without inventing another outcome.
  Arrange `pending-progress.md` with its session path/ID and lesson ID but no
  corresponding progress entry; start a genuinely new conversation. Only that
  named session should be loaded for repair. Clear its pending link only after
  readback confirms progress, preserving unrelated entries and manual notes.
- Use independent collections, a confirmed shared complete-context link, a dangling
  link, and a tracked private destination: follow the shared context/privacy rules.

Record executed outcomes and remaining coverage in `docs/lesson-validation.md`.
This scenario list alone is not evidence of a pass.
